# 错误预算计算器：版本化、幂等与结算演示

一个零前端依赖的中文错误预算计算器。它把“仪表盘实时估值”和“已结算告警窗口”明确分开，并演示：

- 成功标准按 **路由 + 请求等级** 区分（状态码、延迟阈值、SLO 均不同）；
- 相同 `reportId` 的重复上报被幂等拦截，不重复消耗预算；
- 新上报中重复出现相同 `requestId` 也不会双重计数；
- 宽限截止线内的迟到记录会创建新的数据版本，过去窗口的分子/分母和告警等级可以被修订；
- 每个预算结论可展开分子、分母、公式、来源批次、失败请求、版本哈希和版本历史；
- 窗口按水位线结算后，正式告警快照和运营消息被冻结；
- 超过截止线或结算后到达的数据进入更正台账与实时试算，不会静默覆盖正式结论；
- 只有人工显式发布“更正通告”，运营端才会收到新消息；该消息是新增通告，不是矛盾的静默改判。

## 运行

需要 Node.js 20+。

```bash
npm start
# 打开 http://127.0.0.1:4173
```

也可以直接用浏览器打开 `index.html`：页面引用预构建的经典脚本 `src/app.bundle.js`，不依赖 `file://` 下受限的 ES Module 加载。`src/app.js` 与 `src/engine.js` 仍是可测试的 ES Module 源码；修改源码后可用下面命令重新生成 bundle：

```bash
npx --yes esbuild src/app.js --bundle --format=iife --target=es2022 --outfile=src/app.bundle.js
```

## 测试

```bash
npm test
```

测试使用 Node 内置 test runner，覆盖策略差异、幂等、迟到修订、结算冻结和更正流程。

## 推荐演示路径

页面默认已载入 `r1`，也可以点击“自动播放完整修订过程”。

1. **v1 初始批次**：`POST /checkout · critical` 为 `2/40` 失败，错误预算消耗 `500%`，显示严重告警。
2. **重发同一 `reportId`**：返回 `duplicate`，分子、分母和 `r1·hash` 均不变。
3. **宽限内迟到批次**：新增 200 条成功请求，结论变为 `2/240`，消耗 `83.3%`，严重告警降为预警，版本变为 `r2·hash`。
4. **结算窗口**：在 `10:07 UTC` 水位线冻结 `r2`，运营端收到且只收到一条正式预警。
5. **过晚批次**：新增 4 条失败和 6 条成功，实时全量估值变为 `6/250`、消耗 `240%`、严重；但正式结算仍保持 `2/240 · warning · r2`。该批次只生成更正记录。
6. **发布人工更正通告**：运营端新增一条通告，说明候选版本会改为严重；原结算告警不变。

## 核心计算

对于每个 `窗口 × 路由 × 请求等级`：

```text
分母 D = 窗口内匹配策略且唯一的合格 requestId 数
分子 N = 未满足该路由/等级成功标准的 requestId 数
允许错误预算 E = D × (1 - SLO)
预算消耗率 = N / E
```

演示告警规则：

- 消耗率 `< 50%`：健康；
- `50% ≤ 消耗率 < 100%`：预警；
- 消耗率 `≥ 100%`：严重告警。

## 口径与数据版本

- **实时全量口径（live）**：当前账本中所有唯一记录，包含宽限内迟到数据和结算后的更正候选。
- **准入口径（admitted）**：只包含接收时间不晚于 `窗口结束 + allowedLateness` 的记录，是结算使用的口径。
- **正式结算口径（official-settled）**：结算时保存的不可变快照，包含分子、分母、版本号、哈希、告警等级和结算时间。
- **数据版本**：每个预算切片维护递增 `r{n}`，并对纳入分子/分母的规范化记录计算短哈希，例如 `r2·8f3ac21b9d`。重复上报不会产生新版本。
